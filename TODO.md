# TODO

## Current Progress

- `Enaga.Html.Style` has a first internal snapshot invalidation path: `HtmlElementSnapshot` -> `RestyleHint` + `PipelineInvalidation` + estimated `RenderDamage`, plus a per-frame invalidation set that merges multiple snapshots per DOM node.
- `Enaga.Html.Layout` has the first internal formatting/fragment data model: formatting nodes, fragment nodes, visual overflow rects, and fragment damage diffing that unions old/new visual overflow instead of forcing a full-frame fallback.
- Layout now has the first double-dirty path: style/layout versioning emits self/subtree/ancestor layout work dirty bits separately from render damage, `HtmlLayoutOutputStore` invalidates matching per-node layout-output cache entries instead of relying only on version misses, dependency-aware ancestor propagation stops at containment boundaries unless the boundary's own outer layout dependency changed, and layout output cache slots are bounded per node to avoid live-resize cache growth.
- The existing HTML frame source now builds an internal fragment tree from current placed layout nodes and can return fragment dirty rects for hover paint and hover layout changes instead of repainting the full viewport.
- Hover and active pseudo-state changes now feed DOM-keyed snapshot invalidation through `HtmlSceneVersionStore` instead of existing only as whole-tree cache key changes.
- `Enaga.Html.Layout` now has an internal `HtmlStyleTraversal` that can resolve DOM-keyed computed styles before formatting-tree construction; scene tree builds consume that precomputed style tree for normal and DOM-mapped hover/active frames, and no longer keep a selector resolver fallback inside formatting construction.
- Button default hover/active interaction no longer overwrites author-provided hover background or border colors when only one side still has the UA default value; hover clear is covered by regression tests.
- Scroll updates now recompute hover against the scrolled commit in the same frame, so the element under a stationary pointer changes as content moves instead of leaving stale hover state behind.
- Hover/link/text-input hit testing now rejects nodes clipped by ancestor scroll viewports, preventing offscreen scrolled content from taking hover outside its visible scroll container.
- CSS hover/active state is now DOM-keyed end-to-end for style/cache identity. Hit-testing resolves the deepest visible DOM target from layout boxes, link fragments normalize back to the anchor DOM node, and scene ids are no longer used as pseudo-state cache keys.
- Fragment dirty rects are converted to screen coordinates for root-scrolled documents before partial repaint, so hover repaint clips track the visible cells instead of stale content-space positions.
- `examples/SampleBrowser` has an opt-in `--input-log` / `--log-input` mode that logs pointer, wheel, viewport, root scroll, dirty rect, and hit-candidate details for native-window debugging.
- HTML input hit-testing now rebuilds a reusable commit-local uniform-grid spatial index from HTML fragments when hit-test geometry changes, carrying fragment border/overflow boxes, DOM node ids, DOM depth, and paint z-order into separate DOM hover, link, text-input, and scroll-view channels while reusing entry, cell, active-id, and paint-order buffers across commits.
- The internal fragment tree now emits generated scrollbar gutter/thumb fragments for root and nested scroll containers from the resolved commit layout, carries generated fragment roles without per-fragment generated-id string allocation, and lets hit-test consumers resolve generated fragments back to source layout boxes.
- Scrollbar geometry resolution now lives in the core scene layer and is shared by layout fragment generation, input dragging, and Skia painting instead of being duplicated in HTML layout.
- OpenGL live resize now separates drawable resize from content backing-store invalidation: the content framebuffer grows with slack and is reused for smaller resize steps, so resize frames no longer force full scene invalidation solely because the window target changed.
- Allocation work has started from profiler data: font candidate enumeration no longer allocates iterator/LINQ `Distinct` objects on hot paths, common `SKFontStyle` instances are cached, system font fallback is cached in family/style/language buckets keyed by codepoint, glyph support checks use scratch `SKFont.GetGlyphs` buffers instead of `SKTypeface.ContainsGlyphs` temporary arrays, viewport/container unit resolution skips `HtmlComputedStyle`/`HtmlSceneNode` clones when no units need resolving, the HTML hit-test index stores screen rect value types instead of cloned `SceneLayoutBox` screen boxes, inline line layout now uses scratch-backed spans instead of per-layout `InlineLayoutItem` lists/arrays and temporary frame arrays, Skia painting now reuses bounded text blobs across equivalent text runs when the scene commit must be re-recorded, ellipsized line construction is cached separately from full text layout by text/font/width, SKPicture recording culls node self-paint when Skia's current clip/matrix rejects the node paint bounds, dirty-rect frames with changed commits can now paint directly through the clipped Skia canvas instead of first recording a full-scene picture, and scroll containers now reuse bounded content pictures keyed by child subtree signature so scroll-offset-only frames do not replay every child draw command.
- CSS `text-shadow` now flows through computed style, scene text style, visual overflow/damage estimation, and Skia text painting.
- Full-scene `SKPicture` reuse is disabled for now because disposing the retained picture can crash in SkiaSharp and because recording scroll raster tiles under an unscaled picture path degrades viewport-scale zoom quality. Scroll content raster tile caching is also disabled when the canvas is scaled/skewed, so zoom does not upscale cached raster tiles.
- Scroll container painting now uses the active clip bounds to skip child subtrees outside the visible/dirty region, reducing traversal when small hover dirty rects repaint large tables or long scroll content.
- HTML root/window scroll containers now enable horizontal scrolling for `overflow:auto/scroll`, infer root content width from overflowing descendants, reserve bottom scrollbar gutter during layout, emit generated horizontal scrollbar fragments, and support horizontal thumb dragging through the same scene scroll controller path as vertical scrolling.
- `<select>` now has DOM-node-keyed renderer state and a generated popup overlay path: clicking a select opens option rows in the scene commit, option clicks update the selected display text, and the popup closes without treating select controls as editable text inputs.
- `Enaga.Html.Layout` and `Enaga.Html.Style` expose these new internals to tests through `InternalsVisibleTo`; they are not public API.
- `Enaga.Html.Dom` now has a small host-facing `HtmlDomDocument` facade for element lookup/traversal, and `examples/SampleBrowser` has the first thin Okojo-backed `window`/`document` bridge with click listener dispatch from renderer DOM hit-testing.

## Rendering Optimizations

- Follow `docs/html-engine-rearchitecture-plan.md` as the owner for the renderer rewrite. Local compatibility patches should either be removed or turned into fixtures during that rewrite.
- Large HTML first target: keep complete structural DOM, formatting, and layout geometry cheap and available for the whole document, but stop materializing full paint/computed-style/display-list data for everything at once. The staged shape should be:
  1. Resolve a compact layout-style snapshot for all layout-participating nodes so scroll size, table row/column geometry, hit-test bounds, and intrinsic measurements remain correct.
  2. Materialize complete computed/paint style only for the viewport plus a small prefetch margin, with DOM-node-keyed cache entries reused as rows/cells enter and leave view.
  3. Track root and nested scroll deltas as explicit diff state, then repaint newly exposed strips/tiles and changed hover/focus fragments instead of treating large scroll containers as full dirty regions.
  4. Treat large tables as a primary fixture: row-group, row, and cell layout must remain deterministic for total scroll height and column sizing, while paint/style/display-list work is limited to visible rows and near-visible rows.
  5. Keep fallback correctness for selectors that can affect descendants (`:hover`, child/descendant selectors, future sibling selectors) by widening the visible materialization/invalidation scope only when selector dependency maps require it.
- Current temporary optimization target: large link/table pages must make mouse hover target changes paint-only when CSS changes only color/background. Dynamic paint must flow through shared `Enaga.Scene` paint override/display-list concepts, not by cloning compatibility `SceneLayoutBox` entries in HTML. Fall back to the full pipeline for hover rules that affect layout, text metrics, generated structure, descendants that cannot be proven paint-only, or unsupported selector dependencies.
- Extend the new pipeline counters beyond frame snapshots into benchmark output and trace events.
- Split `HtmlComputedStyle` into explicit stages: parsed declaration blocks, cascaded/computed style, used style, and compact layout/paint style snapshots. `HtmlComputedStyle` should stop owning CSS parsing, UA defaults, used-value resolution, and layout adaptation at the same time.
- Continue moving style traversal before formatting-tree construction. `HtmlSceneTreeBuilder` now consumes DOM-keyed styles for normal and pseudo frames; next step is adding generated fragment metadata for carets, focus rings, cursor regions, and selection ranges instead of deriving them from compatibility layout boxes.
- Continue wiring DOM-keyed `ElementStyleData` into the main style state path. Snapshot classification exists for id/class/style/attribute/pseudo changes; next step is to feed it from actual DOM/input mutations before formatting nodes are rebuilt.
- Add Stylo-like invalidation maps for selector dependencies. Start with id/class/tag/attribute/pseudo buckets, then add descendant, child, sibling, and relative-selector invalidation as selector support expands.
- Continue replacing hovered/active/viewport whole-tree cache keys with targeted restyle and damage. Hover/active snapshots now enter the style store as DOM node ids and scene tree caching no longer keys by scene pseudo ids; next step is true subtree restyle/damage roots.
- Add a DOM-keyed hover paint overlay store as the bridge toward retained display lists: first support `a:hover`/link text color and simple table row/cell background-color through scene-level sparse paint overrides, then generalize to paint-only declaration diffs from selector dependency maps. This overlay should update only visible/near-visible fragments and emit dirty rects for old/new paint bounds.
- Expand the initial formatting tree model separate from DOM, styled scene nodes, layout result, and final `SceneLayoutCommit`. It must represent anonymous blocks, generated list markers, table formatting objects, inline boxes, `display:none`, and later `display:contents`.
- Expand the initial fragment tree model into the output of layout. Inline text, line boxes, images, blocks, and table cells should produce fragments with border bounds and visual overflow bounds; scrollbar gutter/thumb generated fragments now exist and still need consumer integration.
- Continue wiring fragment damage diffing into frame production. Hover paint/layout changes now use fragment dirty rects; document reload, resize, and broader style changes still need targeted dirty-root handling.
- Keep `SceneLayoutCommit` / `SceneLayoutBox` as compatibility adapter output, not the primary HTML layout result. `SceneLayoutBox` is still too allocation-heavy as a sealed record for the renderer hot path; migrate HTML internals toward compact fragment/layout/paint snapshots and retained display-list entries, then keep `SceneLayoutBox` only at the compatibility boundary until downstream consumers are moved.
- Move scrollbar gutter reservation into used style/layout constraints for scroll containers. HTML layout should not inject scrollbar width by patching padding-like values in ad-hoc layout builder calls.
- Replace the global layout cache dictionary with a per-node cache model: final-layout slot plus bounded measurement slots keyed by known dimensions and available space. The first dirty-node invalidation path now uses per-node cache buckets and bounded slots instead of full-cache scans or unbounded live-resize growth.
- Expand containment boundaries and dependency-aware layout dirty propagation beyond `contain:size` / fixed-size scroll or clip boxes into axis-specific dependencies, full layout containment semantics, abspos/fixedpos containing blocks, and percentage/intrinsic-size dependency tracking.
- Add local regression fixtures for the current SampleBrowser scrollbar/resize/view-scale failures, including startup frame, fast resize, slow resize, OpenGL live resize, Vulkan live resize, and root/body width mismatch cases.
- Expand the initial paint-side text blob cache into a device-scale-aware text paint cache shared with future retained display-list nodes.
- Extend clipped text layout caching beyond ellipsis into multi-line clipped ranges and text input scroll windows.
- Add text shaping, glyph metrics, intrinsic size, and line-break caches before adding broad layout-result caching.
- Pool short-lived layout arrays in layout-pass arenas for child requests, intrinsic requests, inline runs, line candidates, table row/column buffers, and frame arrays. Do not keep pooled spans in result objects.
- Cache intrinsic node measurements by node id, style version, available width, and text/font version.
- Split scene painting into retained display lists for static subtrees and dynamic overlays such as caret, selection, hover, and scrollbars. Sparse scene-level paint overrides are the first transition step; next, move override application below commit enumeration so display-list nodes can apply dynamic paint without re-recording static subtree structure.
- Replace direct dirty-rect traversal with retained subtree display lists so changed commits can reuse static subtree pictures instead of walking the full scene.
- Promote scroll content picture caching into the retained display-list store once fragment/subtree paint versions are available instead of hashing child subtrees during paint.
- Extend Skia picture recording culling from node self-paint into subtree/display-list culling once fragment visual overflow bounds are available for all children.
- Add display-list stores keyed by fragment/subtree paint version, then use display-list diffs and visual overflow for paint invalidation.
- Add a layer tree and raster/tile cache plan after retained display lists exist. Transform and opacity should become composite-only when a layer boundary is available.
- Batch image decode/upload invalidation so scrolling does not synchronously touch image state.
- Make async image intrinsic-size changes and font-load changes produce targeted layout/paint damage instead of whole-document rebuild.
- Add viewport tile or dirty-region culling for large scroll containers.
- Continue reducing resize GPU cost by avoiding full-frame present/copy during resize settle frames when the backend can preserve content and the dirty rects only cover exposed or changed regions.
- Wire scrollbar generated fragments into display-list consumers so paint no longer infers scrollbar regions from compatibility layout boxes.
- Add fragment channels for text selection/caret positions, focusable regions, focus rings, and cursor changes.
- Add targeted benchmarks for text layout, HTML scene build, resize, wheel scroll, and paint.
- Add BenchmarkDotNet or traceable benchmark cases for parse, CSS rule index, cold style resolve, class/hover mutation, cold layout, resize layout, inline long text, table layout, display-list build, scroll-only frame, and image-ready frame.
- Include stage counters in benchmark output: nodes matched, cascaded, restyled, laid out, fragments rebuilt, display commands rebuilt, cache hits/misses, dirty rect count, and dirty rect area.

## HTML/CSS Coverage

- Replace the current flex/node-based inline approximation with a real inline formatting context: inline item stream, bidi/script/font boundaries, shaping, line breaking, line boxes, baselines, and fragments.
- Add inline support for CJK line breaking, punctuation rules, tabs, non-breaking spaces, `white-space`, `word-break`, `overflow-wrap`, `text-overflow`, inline-block atomic boxes, replaced elements, and list markers.
- Add text pipeline support for bidi resolution, script itemization, font fallback, shaping cache, line-break cache, baseline metrics, and caret/selection mapping.
- Expand CSS selector support: attribute selectors, pseudo classes beyond hover, `:active`, `:focus`, `:first-child`, `:nth-*`, `:not()`, `:is()`, `:where()`, sibling combinators, and selector invalidation data for each.
- Expand CSS cascade support: origin/layer/order handling, `!important`, inheritance keywords, custom properties, shorthand expansion, media/supports/container rule conditions, and environment-version invalidation.
- Expand display and formatting support: `display:contents`, `list-item`, table display types, anonymous table boxes, `inline-block`, `inline-flex`, `grid` placeholders, and proper `display:none` state retention.
- Expand sizing support: `auto`, min-content, max-content, fit-content, intrinsic sizes, aspect-ratio, percentage sizing in indefinite containers, margin auto, logical properties, and writing mode aware inline/block axes.
- Expand positioning support: absolute, fixed, sticky, containing blocks, inset resolution, z-index, stacking contexts, and transform-origin.
- Expand table support: auto/fixed table layout, captions, colgroup/col, row/col span distribution, border-collapse conflict resolution, border-spacing, and vertical alignment.
- Expand paint support: layered backgrounds, background-position/repeat/clip/origin, per-corner border radius, per-side border styles/colors, outline, richer box-shadow/text-shadow visual overflow, opacity, transforms, filters, clipping, and text-decoration propagation.
- Expand resource support: raster image intrinsic sizes, SVG intrinsic sizing without ad-hoc string parsing, async image load invalidation, web font loading, font fallback, and decode/upload lifecycle separation.
- Expand scrolling/interaction support: axis-specific overflow-x/y parsing, nested scroll containers, scrollbar gutter/width/color, scroll hit testing, cursor changes, focus rings, text input selection/caret, select keyboard navigation/change events, anchor navigation, and keyboard focus traversal.
- Add more default UA stylesheet behavior for forms, tables, images, links, headings, lists, replaced elements, and text inputs.
- Grow the DOM/JS bridge incrementally from the thin host facade: event target identity/bubbling controls, `onclick` parity, DOM mutations that feed style invalidation, and focused form APIs should stay DOM-keyed instead of adding browser assumptions to the viewer.
